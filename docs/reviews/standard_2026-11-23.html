  • テスト 25 件合格 (静的・積分法回帰・短い GA run の再現性)。
  • 10 世代 × 20 個体 × 5 秒の evolve が 1.25 秒 (JIT 込み) で完了、GPU メモリ 236 MB (OOM なし)。
  • 再現性: 同一 seed で rel 1e-5 で一致 (tests/test_reproducibility.py)。

3. 修正推奨

R1. src 自動修正可 replay が保存された身体定義を使わない

箇所src/bodyopt/cli.py:80: cmd_replay — spec = creature_from_summary(meta["creature"]) (修正後)
問題点旧実装は replay 時に _creature(args) で身体を作り直していたため、実行時の --n-cols 既定値が変わると過去 run の再生が壊れる。記録の再現性 (遺伝子 + commit + params で同じ物理) を損なう。
正本docs/agents/SPEC.md §7 —「軌跡は遺伝子 + commit + params で再現できることを前提に」
修正案meta.json の creature 概要から CreatureSpec を復元する (io.creature_from_summary)。概要に masses・stiffness・muscle_mask を追加し、旧形式 meta にもフォールバック対応。
影響範囲io.creature_summary の保存項目が増える (向後互換は維持)。cmd_replay のみ。

修正完了: io.creature_from_summary を追加し cli.cmd_replay を切替。pyright・pytest 25 件・replay --generation 9/0 の再実行で dx と滞空率が旧実装と一致することを確認した。

R2. src 自動修正可 rollout の未使用変数

箇所src/bodyopt/physics.py:rollout — (pos_T, vel_T, _), outs = jax.lax.scan(...) (修正後)
問題点scan の最終 carry のうち時刻 t_T だけ未使用だった (times は arange で再構築)。可読性の軽微な問題。
修正案アンダースコアで受ける。

修正完了: pytest 25 件合格で同一挙動を確認。

R3. docs 自動修正可 viewer が creature の辺順序を再実装している (硬結合)

箇所viewer/index.html:ladderEdges — pairs.push([i, i+1], [nCols+i, nCols+i+1], [i, nCols+i], [i, nCols+i+1])
問題点viewer は src/bodyopt/creature.py の辺順序を JS で再実装している。creature.py の接続規則を変えたとき viewer が黙ってずれる。
正本docs/agents/SPEC.md §7 —「creature.py の接続規則を変えたら viewer 側も同じ順序に更新すること」(本 review で追記)
修正案恒久対応は軌跡 JSON に edges・base_pos を同梱し viewer 側の再実装を削除すること。次回のビューア強化 (報告 0001 の todo) で実施する。
影響範囲軌跡 JSON のサイズがわずかに増える。viewer の読込部。

持ち越し: 恒久対応は次回のビューア強化と合わせて実施 (報告 0001 の todo「ビューアの強化」と同根)。当面は SPEC の注意書きで運用。
