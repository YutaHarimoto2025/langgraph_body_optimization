報告 2026-11-23｜first goal の固定 GA run と跳躍解の観察

2026-11-23｜対象: src/bodyopt (初回実装)｜生データ: resources/runs/first_try/

first goal の動作テストとして、固定 GA (10 世代 × 20 個体 × 5 秒) を GPU 上で 1.25 秒で完走させた。GA の探索は機能しているが、評価が「右向き重心変位のみ」のため、GA が選んだ最良個体は歩行ではなく大跳躍 (滞空率 64%、重心最高 5.8 m) で距離を稼ぐ解だった。アイデアメモ §4 が予測した reward hacking の初期兆候であり、次の判断 (跳躍への罰則かエネルギー制約か) を迫る結果を得た。

目的 追加機能 実験設定 資源と時間 主要な結果 分析 todo との照合

その回の目的

LangGraph・LLM を使わない純粋 GA で「2D 質点・バネ身体の周期制御最適化」が end-to-end で動くことを確認する (@docs/agents/overview.md の first goal)。合わせて、合意した運用サイクル (静的テスト → 短い GA run による動的テスト → docs 正本化 → 報告) を初めて一巡させる。

追加したもの

  • JAX シミュレータ (src/bodyopt/physics.py): 半陰的オイラー法 (第一候補) と RK4 (比較用)。1 個体分の物理を書き、集団は vmap、時間は lax.scan、世代も 1 つの jit + scan に統合。床接触は臨界減衰 (c_contact = 2√(k_c m) ≈ 89.4) に変更した (初値 50 は不足減衰で接触面のトランポリン化を助長するため)。
  • 評価関数 (fitness.py): 重心の右向き変位、無効判定 (非有限・めり込み 10 cm 超)、駆動仕事の記録 (筋肉がバネに注入した正の仕事)。--energy-budget オプション (既定は無制限)。
  • 固定 GA (ga.py): トーナメント選択・一様交叉・ガウス変異・エリート継承。世代ループ内の CPU 同期は tree.map(np.asarray) の 1 回だけ。
  • 記録・CLI (io.py・cli.py): evolve (headless) と replay (保存個体の再ロールアウト) を分離。summary / population / full の 3 記録レベルと、git commit hash・seed・全パラメータを含む再現メタデータ。
  • three.js ビューア (viewer/index.html): 軌跡 JSON を読み込み、視点移動できる 3D 表示で再生する (2D 物理を 3D 空間に配置)。張力の色分け・接触点・重心軌跡・駆動仕事の表示つき。

実験設定

ケースは 1 種 (first_try)。物理・GA の既定値は params/default.json のとおりで、コマンドは次のとおりだった。個体ごとの全データは population.npz、再現メタデータは meta.json を参照。

uv run python -m bodyopt evolve --generations 10 --seed 0 \
    --record full --out resources/runs/first_try

主要な結果

GA の探索は機能した。best score は 1.234 m (世代 0) → 1.422 m (世代 5) → 1.778 m (世代 9) と単調に改善し、全世代で valid rate 1.0、同じ seed で再実行すれば距離は rel 1e-5 で一致する (tests/test_reproducibility.py)。単一評価 (1,000 ステップ) はウォームアップ後 0.11 秒/個体、集団評価は vmap で一括した。

ただし最良個体の移動様式は歩行ではない。最良個体 (世代 9) の軌跡を再生すると、重心は最高 5.79 m まで上昇し、全質点が非接触のフレームは 63% を占める。つまり身体は接地・踏切を繰り返しながら弾道で飛び、5 秒で 1.78 m を稼いでいる (世代 0 の最良も同じ様式、重心最高 4.97 m・滞空 64%)。

分析・先行研究との差異

何が起きているか。筋肉は基準自然長 (0.4〜0.64 m) を最大 20% 縮めるだけで、質量 6 kg・剛性 100 N/m の身体に各辺あたり ~0.8 J を注入できる。全 9 辺が位相を揃えて収縮・弛緩を繰り返すと、床との接触バネ (2,000 N/m) にエネルギーが蓄えられ、踏切として一気に解放される。評価が変位のみで跳ねた高さを罰しないため、GA にとって「弾道で飛ぶ」は最も費用対効果の高い戦略だった。世代 9 の最良が振幅の平均 0.13 (9 辺中 4 辺が 0.18 超) に達しているのはこの圧力の表れである。

積分法への影響。跳躍解は踏切の初速に数値誤差がそのまま飛距離として効くため、scheme 間で距離が 0.1〜0.2 m 変わる (tests/regression/ の実測: GA 最良個体が 5 ms / 2.5 ms / RK4 で 1.49 / 1.37 / 1.34 m)。一方、無駆動個体は 3 手法で完全一致 (0.001 m 未満)、位相が跳躍を引き起こさない個体 (amp ≈ 0.10) は 0.02 m 以内で一致した。つまり scheme 感度は「解の側 (跳躍モード)」に帰属し、第一候補の半陰的オイラー法 (5 ms) は歩行解の評価には十分だが、跳躍解の距離を信用してはいけない。

先行研究との差異。Rojas (2016) は同種の周期制御 GA で「小刻みな歩行」を得ているが、あちらは (a) 変形三角形メッシュの有限要素で接地面が柔らかくトランポリン化しにくい、(b) 筋肉の収縮率が辺長に対して小さい、(c) 探索対象が周波数で振幅上限が小さい、という違いがある。本実験は質点・バネの単純さと振幅 20% の余裕が「踏切・滑空」を最適にした点で、単純モデル特有の failure mode を早期に見せてくれた。アイデアメモ §4 の「身体を吹き飛ばす解」の予測と整合する。

新規性。LLM 介入などの拡張はまだないため、本報告の新規性は「GA が選ぶ解のモード分類 (歩行 vs 跳躍) と scheme 感度の対応関係を実測した点」に限られる。この観察が、次の評価設計 (罰則・制約の選択) の判断材料になる。

残っている todo との照合・拡張案

  • 跳躍解への対処 (新規・最優先)。合意した順序は「まず変位だけでやり、意図しない解が観測されたら罰則を追加」。観測されたので、次の報告では次の 3 案を比較する: (1) 滞空率・重心最高高さの罰則、(2) --energy-budget (実装済み・未使用) の実値での効果測定、(3) 摩擦・接触剛性の変更で踏切が有利にならない条件の探索。いずれも比較方式間で評価式は固定する。
  • 刻み頑健性の保証。跳躍解が選ばれる間、GA 最良個体の scheme 間一致 (0.05 m) は保証できないため、回帰テストは破綻防止 (0.5 m) に留めてある (tests/regression/test_best_individual_scheme.py)。跳躍対策後に 0.05 m へ厳格化する。
  • エネルギー記録の活用。距離 1.78 m に 51 J (28.8 J/m) を要した。罰則導入後は「距離あたり仕事」の分布を世代曲線と並べて報告し、budget の初期値の根拠にする。
  • first goal の残件。docs/humans/spec.html の進捗表にある形状探索・LangGraph・feedback 制御は今回手つかず。合意どおり first goal (本報告の動作確認) 達成後に着手する。
  • ビューアの強化。現状は 1 個体の再生のみ。次は世代選択・複数個体の比較・スコア推移パネル (shadcn/ui 検討) を加える。

次回までの判断事項:跳躍への対処として罰則・エネルギー制約・物理調整のどれを先に試すか。報告者の暫定スタンスは (1) の滞空率罰則 (実装が最小で、合意の J = d − λ·罰則 に直接対応する) を第一候補とし、(2) を同時比較とすること。
